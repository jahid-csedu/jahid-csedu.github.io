NewzGator

A news product for Bangladeshi publishers. Readers should see one story, in the right section, with a short summary, even when a dozen papers run the same event. I own four services: the ingestion pipeline, the reader API, the operations console, and the load tests. Live at newzgator.com.

Ingestion pipeline

One Spring Boot process. Work moves on RabbitMQ. Crawl and scrape writes land in outbox tables first, so a broker outage does not drop a link that was already found.

  • The crawler runs on a schedule, per publisher, and only claims a portal it has reserved.
  • The scraper extracts the article, with up to three attempts. Each publisher has its own CSS selectors and JSON-LD rules, and Groovy scripts clean values such as dates after extraction.
  • A successful extract is fanned out to three consumers: category, summary, and cluster.
  • Category comes from the URL when the section is in the path. Bengali text that does not match falls through to an ONNX model. The sections are technology, Bangladesh, international, sports, entertainment, economy, opinion, lifestyle, and education.
  • Summaries go to Groq, then Gemini if that fails, with a pause between calls so the providers are not flooded.
  • Clustering embeds the headline, with BAAI/bge-m3 in production or a local model on my machine. A story joins a cluster from the last 48 hours when the vectors are close enough. Each cluster has one lead article, which is what the feed shows. If the embedding fails, the message is dead-lettered and the article still gets its own cluster.

Reader API

This service does not crawl. It reads what the pipeline has already stored: a cursor feed of lead articles, article detail, related stories, full-text search, trending clusters, categories, and publishers.

  • Reading is public. Sign-in is Google, Facebook, or X, and it unlocks bookmarks, comments, and reactions: like, dislike, important, or inaccurate.
  • Related stories prefer the same cluster, then the nearest headline vector in the same section.
  • Recommendations use the last 30 days of clicks, bookmarks, comments, and reactions. Category and publisher weights choose the candidates. Headline distance reorders them toward stories close to ones the reader actually engaged with. Clicks that came from the recommendation rail are not treated as a preference.
  • A reader with no positive history gets an empty rail, so the client can hide it. Writes are rate-limited. Responses for a signed-in reader are cached for a short window.

Operations console

A Thymeleaf admin app for the pipeline, not for readers. I add a publisher, the pattern that identifies a news URL, and the scrape rules for headline, body, and the rest. I can test a crawl and a scrape against the core service before turning a portal on.

  • The dashboard shows stuck jobs, links still waiting to be scraped, articles waiting on a category, missing summaries, crawls that need attention, and configuration that looks unhealthy.
  • It also lists articles, the latest comments, and basic analytics, so I can see what readers are doing without opening the database.

How it runs

PostgreSQL 16 with pgvector is the system of record. Flyway owns the schema. Each service is a Docker image built in CI. OpenTelemetry exports traces. Gatling runs smoke, browse, and mixed-traffic simulations against the reader API.
